## 2. GenAI の基礎知識

| キーワード                     | 概要                                                                                        |
| ------------------------------ | ------------------------------------------------------------------------------------------- |
| **生成  AI (Generative AI)**   | テキスト・画像・コードなどを「生成」する AI。確率的に次のトークン（単語・記号）を予測する。 |
| **LLM (Large Language Model)** | 大規模テキストを事前学習したモデル。ChatGPT はその一種。                                    |
| **Transformer**                | 2017  年発表。自己注意機構 (self‑attention) で長文の文脈を保持。                            |

> **ポイント** : ChatGPT は “答えを検索” しているのではなく、**最もらしい続きを予測** しているだけ。必ず **事実確認 (Fact‑Check)** を！

### 言語モデリング（Next‑Token Prediction）

> **タスク** : 途中で切れた文章の続きを当てる

```
被害者の最後の言葉: 「犯人は・・」
```

容疑者は **太郎／花子／一郎** の 3  名。

```
容疑者は 太郎・花子・一郎 の誰かだ。
調査の結果、太郎 と 一郎 にはアリバイがあった。犯人は・・
```

LLM は文脈から **「花子」** を予測します。

## 3. 生成  AI で出来ること

- **ドラフト作成** : 企画書、メール、FAQ、求人票
- **コード補助** : 関数生成、テスト作成、リファクタ提案
- **分析サマリ** : 会議録 → 要点抽出、感情分析、次アクション提案
- **ブレインストーミング** : アイデア出し、A/B テスト案、リスク洗い出し

### 利用上の注意

1. **Fact‑Check** : 重要な数値や引用は必ず裏どり
2. **具体的プロンプト** : 曖昧な指示は品質低下
3. **機密データ管理** : 社外共有範囲を超えるデータは貼り付け禁止

## 5. モデル早見表（2025‑Q2）

| モデル                | コンテキスト | 得意分野            | コスト感 | 速度\*   | 典型ユースケース             |
| --------------------- | ------------ | ------------------- | -------- | -------- | ---------------------------- |
| **GPT‑4o** (Mar 2025) | 256k         | 高速・画像・コード  | ★★〜★★★  | ⚡️ 最速 | 画像 → 仕様書, コード生成    |
| **o3**                | 64k          | 深い分析 + Web 検索 | ★★       | ○ 中程度 | リスク分析, 計算付きレポート |
| **o4‑mini-high**      | 32k          | 軽量 Bot            | ★        | ◎ 速い   | チャットサポート, IoT 制御   |

\*速度は社内計測 (平均応答時間) に基づく相対評価：⚡️ 最速 / ◎ 速い / ○ 中程度。

> **Tip** : “最強モデル＝最適”ではない。**タスク × 予算 × 速度** で選択。

## 6. プロンプトの書き方

### 6‑1. なぜ重要か

- **具体性 = 品質** — 曖昧な指示は曖昧な結果につながる
- **再現性** — 良いプロンプトはコピペで再利用できる
- **セキュリティ** — 指示にガードレールを組み込める

### 6‑2. 4 パートテンプレート `Role｜Context｜Task｜Format`

| パート      | 目的               | ベストプラクティス                   | NG 例                |
| ----------- | ------------------ | ------------------------------------ | -------------------- |
| **Role**    | モデルの視点を固定 | 「あなたは**医療 CS リーダー**です」 | 「プロっぽく」       |
| **Context** | 前提・素材を提供   | 箇条書きで要点、機密はマスク         | 「詳細は割愛」       |
| **Task**    | 作業指示           | 動詞＋成果物＋評価基準               | 「いい感じに」       |
| **Format**  | 出力構造を固定     | *文書型*＋貼付けやすい形＋数値制約   | 曖昧な「箇条書きで」 |

> **例**\
> `Role: シニアPM｜Context: プロジェクト概要…｜Task: リスクを3件抽出し優先度順に並べる｜Format: Notionの決まったテンプレなど (列: リスク, 影響度, 対策)`

Prompt

```
 Role: 医療事務スタッフ

Context:
- 明日 (2025/04/29) の外来予約リストを下に貼り付けます
  09:00 田中花子 内科
  09:15 S.K.      小児科
  09:30 佐藤一郎 整形外科
  09:45 Y.M.      内科
- 氏名はフルネームまたはイニシャルで記載済み
- この情報は院内のみで使用

Task:
- 上記リストを **Notion** に変換
- 列: time, patient, department
- ヘッダー行を含めること
- 並び順は時間順で維持

Format:
- Notion 形式
```

Output

```
はい、Notionで使える形式に変換しました！
Notionでは、表（データベース）に貼り付けられるように、Markdown表形式で準備するのが一般的です。

こちらをそのままコピー＆ペーストすれば、Notionの表ブロックとして認識されます：

ruby
Copy
Edit
| time  | patient | department |
|:------|:--------|:-----------|
| 09:00 | 田中花子 | 内科        |
| 09:15 | S.K.    | 小児科      |
| 09:30 | 佐藤一郎 | 整形外科    |
| 09:45 | Y.M.    | 内科        |
```

### 6‑3. 追加テクニック（概要）

| テクニック              | 目的                 | コツ                                           |
| ----------------------- | -------------------- | ---------------------------------------------- |
| **制約条件**            | 再現性向上           | 数値・トーン・形式を明示 (`Format:` 指定など)  |
| **Few‑Shot**            | 出力パターン学習     | 入力例 / 出力例 をセットで示す                 |
| **Chain‑of‑Thought**    | 推論精度向上         | 「ステップバイステップで考えてください」を明示 |
| **自己批評モード**      | 自動ブラッシュアップ | Step1 ドラフト → Step2 自己評価と改善          |
| **Delimiter**           | 長文区切り           | コードブロックやタグで囲む                     |
| **システムメッセージ**  | 強いガードレール     | system ロールで渡す                            |
| **温度制御**            | 創造性/一貫性        | temperature パラメータを調整                   |
| **Iterative Prompting** | 大型タスク分割       | Q→A→ 追質問で段階的に深掘り                    |

### Iterative Prompting

> **ケース：商品 LP（ランディングページ）作成を段階的にブラッシュアップ**

```text
[ターン1] Q: 新製品「EcoBottle」のLPアウトライン（見出し 5 つ）を作成してください。
[ターン1] A: H1: 製品紹介… H2: 特長… H3: 仕様… H4: 口コミ… H5: 購入方法…

[ターン2] Q: H2「特長」を 150 字以内の箇条書き 4 点で詳細化してください。
[ターン2] A: • 100% リサイクル素材… • 軽量設計… …

[ターン3] Q: 今の H2 にユーザー事例 1 つを追加し、説得力を高めてください。
[ターン3] A: • 導入企業 ABC 社で年間 30% のペットボトル削減に成功…
```

このように「① アウトライン → ② 章単位で肉付け → ③ 証拠追加」のように段階的に指示を重ねるのが Iterative Prompting です。
